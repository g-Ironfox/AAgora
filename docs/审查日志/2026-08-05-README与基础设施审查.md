## 二、问题清单

### 高优先级

| # | 位置 | 问题 | 建议 |
|---|------|------|------|
| 1 | `README.md` | 缺少启动说明：compose 依赖 `.env` 中的 `MONGO_USER` / `MONGO_PASS`，但未提及 `cp .env.example .env`、`docker compose up -d --build` 及开发模式命令 | 补充「快速开始」章节，含正式与开发两种启动方式 |
| 2 | `README.md` | 将「AI 生产内容（Agent 式 / Content Generate 式）」描述为平台方法，但当前 WebUI 仅是内存 mock 数据的 CRUD 应用，无 agent、无 AI 生成、无 QQ 接入 | 将愿景标注为「规划中」，与「已实现」分开描述 |

### 中优先级

| # | 位置 | 问题 | 建议 |
|---|------|------|------|
| 3 | `docker-compose.dev.yml` | 注释多次引用 `agent` / `qqbot` 服务（挂载源码、`sleep infinity` 启动），但 `docker-compose.yml` 只定义了 `webui` / `redis` / `mongodb`，agent、qqbot 并不存在 | 修正或删除过期注释，避免误导 |
| 4 | `.env.example` | `DEEPSEEK_*`、`KIMI_*`、`QQ_*`、`REDIS_*`、`MONGO_*` 等变量中，当前仅 `MONGO_USER` / `MONGO_PASS` 被 compose 实际消费；`webui/main.py` 使用内存 `posts_db`，尚未连接 mongo/redis | 在 README 注明「WebUI 数据当前为内存 mock，MongoDB/Redis 已就位待接入」；或移除未使用变量 |
| 5 | `README.md` | `docs/webui-design.md` 已删除后，README 中「方的而不是圆的；节约空间；高效简洁清爽的」成为唯一设计准则记录 | 可将其扩展为简短设计约束清单，或保留精简版设计文档 |

### 低优先级

| # | 位置 | 问题 | 建议 |
|---|------|------|------|
| 6 | `README.md` | 缺少项目名、技术栈、目录结构、License 说明 | 补充标准 README 小节 |
