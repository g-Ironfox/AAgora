## 结论

有条件通过。核心认证链路(注册、登录、会话、退出、鉴权、归属校验)实现正确,满足最小可用要求;无 P0/P1 阻断问题。建议处理 P2 暴力破解防护后再正式上线,并修复 P3 用户名长度校验绕过。

## 已核验

1. 注册 `POST /api/v1/auth/register`:用户名 `strip()` 后校验字符集并 `casefold()` 归一化,配合 `username_normalized` 唯一索引防重名,重复注册返回 409「用户名已被使用」。
2. 密码存储:PBKDF2-HMAC-SHA256,随机 16 字节盐,迭代 600000 次,存储格式 `pbkdf2_sha256$600000$盐$摘要`,不含明文;登录用 `hmac.compare_digest` 恒定时间比较。
3. 登录失败统一返回「用户名或密码错误」,不区分用户是否存在(防枚举)。
4. 会话:令牌 `secrets.token_urlsafe(32)`(256 位随机);数据库仅存 SHA-256 摘要;Cookie `HttpOnly + SameSite=Lax + path=/ + Max-Age=30 天`,`secure` 按 `request.url.scheme` 自动开启。
5. 会话过期由 `expires_at` TTL 索引(expireAfterSeconds=0)自动清理;`get_current_user` 校验令牌哈希与过期时间。
6. 退出幂等:删除会话记录并清 Cookie,无会话时亦正常返回 204。
7. 写操作鉴权:发帖/编辑/删除、点赞/收藏、关注均依赖 `get_current_user`;编辑/删除校验 `post.author_id == current_user.id`,否则 403「只能编辑/删除自己的帖子」。
8. 前端闭环:`/auth/me` 启动恢复会话;登录/注册弹窗可切换、错误回显、提交禁用态;未登录发帖/回复/点赞/收藏/关注均拦截并弹出登录;退出后重置信息流。
9. 缓存修复:静态资源加 `no-cache, must-revalidate`,模块 URL 带统一版本参数,消除 ES Module 新旧文件混载导致 `fetchCurrentUser` 缺失。
10. 部署配置:webui 容器注入 `MONGO_HOST/PORT/USER/PASS/DATABASE`;`.env.example` 数据库名 `aagora` 与代码默认值一致。

## 问题清单

| 级别 | 问题 | 说明与建议 |
|------|------|------------|
| P2 | 登录/注册无速率限制、无锁定策略 | 在线暴力破解可无限尝试(600k 迭代只拖慢离线破解);建议对登录失败计数、同 IP/同用户名限速,或接入 Redis 做限流 |
| P3 | 用户名最小长度可被空白填充绕过 | `Field(min_length=2)` 在 validator strip 之前校验原始值,`" a "` 通过长度检查后 strip 为单字符 `a`,且字符集允许 1 位用户名;建议在 validator 内对 strip 后长度再校验 >=2 |
| P3 | 注册接口可枚举用户名 | 注册 409 暴露用户名占用,与登录 401 策略不一致;属常见取舍,如需严格防枚举可统一返回 200/409 模糊化 |
| P4 | CSRF 防护依赖 SameSite=Lax | 当前仅靠 `SameSite=Lax` 防御跨站状态变更;内网/同域部署可接受,公网多域名部署建议加 CSRF Token 或自定义请求头校验 |
| P4 | Cookie `secure` 依赖 `request.url.scheme` | 若未来置于反向代理之后,未透传协议头时可能误判为 http 而不加 Secure;上线前按部署形态复核 |
| P4 | 无密码修改/重置与登出全部会话 | 当前仅注册/登录/退出;密码泄露后无法主动吊销,建议后续补密码修改并清除旧会话 |
| P4 | 头像依赖外部 dicebear 服务 | 页面展示需访问第三方 CDN,存在外链可用性/隐私风险;可后续改为本地生成或用户上传 |
