# 2026-08-06 WebUI 导航去重与前端模块拆分-审查报告

> 日期:2026-08-06。
> 类型:审查报告。
> 性质:历史快照。
> 范围:AAgora WebUI 删除「大家在聊」导航入口(与「热门」重叠),并将帖子弹窗逻辑从 main.js 拆分为独立模块 post-modals.js。
> 说明:静态审查,无测试环境,未做运行时验证;结论基于源码逐行核对与 VS Code 静态诊断。

## 结论

有条件通过。导航去重方向正确:「大家在聊」与「热门」经核实指向同一 `popular` 查询,删除侧栏入口、保留顶部按钮,行为无损失。模块拆分是纯重构,迁移逐项比对保持行为等价,无 P0/P1 阻断问题。P2 为未在真实浏览器回归全部帖子交互;P3 为 main.js 缓存版本号未同步递增。

## 已核验

1. 功能重叠成立:侧栏「大家在聊」点击后 `selectFeed('discussed', 'popular')`,与顶部「热门」`selectFeed('market', 'popular')` 同走 `sort='popular'` 查询(点赞数、回复数、创建时间倒序),数据与 UI 完全重复,删除其一合理。
2. 去重彻底:index.html 已删除 `data-view="discussed"` 链接;main.js 移除 `view === 'discussed' ? 'popular' : 'latest'` 分支;全局搜索无 `discussed`/「大家在聊」残留;「热门」仍为唯一 popular 入口。
3. 模块边界:post-modals.js 通过工厂 `createPostModalController` 注入 `getCurrentUser`/`resetFeed`/`requireUser` 回调,无循环依赖;main.js 只保留启动、状态、导航、feed 加载与点赞/收藏。
4. 导入整洁:post-modals.js 导入的 6 个 API(`createPost`/`deletePost`/`fetchPost`/`fetchPosts`/`toggleFollow`/`updatePost`)全部被使用;main.js 已移除不再使用的 5 个 API 导入,保留的均在使用。
5. 行为等价(逐项核对):
   - 发帖/回复:提交成功 `await resetFeed()`(内部重置 `currentPage=1`),等价原 `currentPage = 1; resetFeed()`;提示文案与错误分支一致;
   - 未登录拦截:`showAuthRequired()` → `requireUser()` 等价原 `if (!currentUser) { showAuthModal('login'); return; }`;
   - 详情弹窗:回复列表渲染、`attachPostCardListeners(modal)` 绑定、详情内「回复」→ `showReplyModal`、关注作者按钮逻辑与提示全部保留;
   - 编辑/删除:确认弹窗、`updatePost`/`deletePost` 调用、成功提示与 `resetFeed` 保留。
6. 登录态实时性:`getCurrentUser: () => currentUser` 为闭包箭头函数,登出/登录后弹窗模块读取最新用户,无需重建;初始化时序(postModals 于 restoreSession 后、loadPosts/FAB 绑定前创建)保证卡片事件访问时控制器已就绪。
7. 静态诊断:index.html、main.js、post-modals.js VS Code 静态检查全部无错误。

## 问题清单

| 级别 | 问题 | 说明与建议 |
|------|------|------------|
| P2 | 无测试环境,帖子交互未回归 | 模块拆分覆盖发帖/回复/编辑/删除/详情/关注/收藏全部交互,属纯重构但改动面广;上线后需用户实测上述流程及未登录拦截 |
| P3 | `index.html` 中 main.js 缓存版本号未递增 | `<script src="/static/js/main.js?v=20260806-stable-first-paint">` 未随内容更新;依赖后端 `no-cache, must-revalidate` 兜底仍可生效,但按项目惯例(静态资源依赖 `?v=` 破缓存)应递增,如 `?v=20260806-post-modules` |
| P3 | `postModals` 为模块级可变状态 | 若未来在 `init()` 之前触发卡片事件(当前不存在该路径)会访问未初始化变量;属防御性提示,可在控制器创建处集中保证时序 |
| P4 | 模块命名与职责宽度 | `post-modals.js` 实际含详情弹窗内的关注作者逻辑,略超「弹窗」语义;可接受,后续若关注逻辑扩展再拆 |

## 验证方式

- 静态证据:逐行阅读 `webui/static/js/main.js`(导入、状态、卡片监听、bindNavigation、init 接线)、`webui/static/js/post-modals.js`(工厂、5 个弹窗方法、辅助函数)、`webui/static/index.html`(导航与 script 标签);`git diff` 核对迁移前后行为等价(main.js 约 700→440 行,新增 post-modals.js 约 240 行)。
- 全局搜索:确认 `discussed`/「大家在聊」零残留;main.js 无被删除函数名的引用。
- VS Code 静态诊断:index.html / main.js / post-modals.js 均无错误。
- 未验证项:无测试环境,未实测发帖/回复/编辑/删除/详情/关注/收藏、登录拦截、模块加载顺序与浏览器缓存失效行为;`node --check` 语法校验因用户取消未执行,以 VS Code 静态诊断为准。

## 涉及文件

- `webui/static/index.html`(删除「大家在聊」导航链接)
- `webui/static/js/main.js`(移除 discussed 分支、弹窗逻辑与无用导入,接入控制器)
- `webui/static/js/post-modals.js`(新增:帖子弹窗控制器)

## 建议

1. 上线前:在浏览器实测发帖/回复/编辑/删除/详情/关注/收藏及未登录拦截(P2),确认模块拆分无行为回归。
2. 顺手补 `index.html` 中 main.js 的缓存版本号递增(P3),与新模块 `?v=20260806-post-modules` 保持一致。
3. 后续迭代:控制器工厂模式可作为前端分层范本,后续新增功能(用户主页、通知等)按「模块 + 依赖注入」拆分;注意新模块引入的 API 若被 main.js 复用,应评估放共享层。
4. 具备测试环境后:补前端 E2E(导航去重后「热门」仍按 popular 排序、五类帖子弹窗交互、登录拦截、模块加载)。
