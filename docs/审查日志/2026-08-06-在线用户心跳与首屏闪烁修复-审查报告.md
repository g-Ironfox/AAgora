# 2026-08-06 在线用户心跳与首屏闪烁修复-审查报告

> 日期:2026-08-06。
> 类型:审查报告。
> 性质:历史快照。
> 范围:AAgora WebUI 在线用户 Redis 心跳统计、前端心跳链路、Redis 配置环境变量化、首屏两阶段渲染闪烁修复。
> 说明:静态审查,无测试环境,未做运行时验证;结论基于源码逐行核对与 VS Code 静态诊断,部署验收未见明显 bug。

## 结论

有条件通过。在线用户语义(注册总数→2 分钟活跃窗口)与首屏闪烁修复方向正确,实现自洽,无 P0/P1 阻断问题。建议处理 P2 Redis 故障降级与 P3 登出多标签页波动后再正式上线,并清理死代码。

## 已核验

1. 在线用户改为 Redis ZSET 活跃窗口:心跳 `ZADD presence:users <user_id> <ts>` 幂等去重;`get_stats` 先 `ZREMRANGEBYSCORE` 清过期再 `ZCOUNT` 统计,语义与实现一致。
2. 窗口与心跳比例 2:1(120s / 60s),容忍一次心跳丢失;`visibilitychange` 回到可见时补发心跳并刷新统计。
3. 心跳鉴权:依赖 `get_current_user`,未登录 401;前端对 401 静默,其余错误打印,不会刷屏。
4. 心跳生命周期完整:init 恢复会话后启动、登录/注册成功启动、登出停止,`startPresenceHeartbeat` 先 `clearInterval` 防重复定时器。
5. 登出即时下线:先查 session 取 `user_id` 再 `ZREM`;session 已被 TTL 清理时跳过,幂等。
6. 首屏闪烁根因识别正确:空 feed 先插骨架卡片再整体替换,登录区空→按钮/头像二次渲染;移除首屏 `renderSkeleton()` 与 `pulse` 动画、登录区固定宽度,消除两阶段绘制与横向重排。
7. 缓存策略:主脚本/样式 URL 带版本参数,配合后端 `no-cache, must-revalidate`,防旧模块混载。
8. Redis 配置环境变量化:`auth.py` 默认 `redis:6379`,compose 注入 `REDIS_HOST/PORT` 并加 `depends_on: redis healthy`;`.env`/`.env.example` 已同步。
9. 静态诊断:Python / JavaScript / HTML / CSS 全部改动文件无错误;改动已提交 `1eac082`,工作区干净。

## 问题清单

| 级别 | 问题 | 说明与建议 |
|------|------|------------|
| P2 | Redis 故障无降级 | `get_stats`/`heartbeat` 直连 redis_client,Redis 不可用时前者 500、后者前端报错;建议包 try/except,统计降级返回 `users: null` 或跳过,心跳失败仅记日志,避免连带统计接口挂掉 |
| P3 | 多标签页登出会移除整个用户在线状态 | 任一标签页登出即 `ZREM` 该 user_id,其余标签页 60s 内心跳才加回,存在短暂波动;可在登出时只删 session、保留 presence,靠窗口自然过期 |
| P3 | 离线判定滞后 2 分钟 | 60s 心跳 + 120s 窗口为折中,用户关闭页面后最多 2 分钟内仍计在线;对社区首页可接受,需明确预期 |
| P3 | 统计接口带写副作用 | `GET /stats` 每次执行 `ZREMRANGEBYSCORE` 写操作;ZSET 操作原子可接受,但语义上 GET 非纯读,后续可改为心跳时顺带清理或独立定时任务 |
| P4 | 死代码残留 | `renderSkeleton()`、骨架 CSS 类无调用方;`is-refreshing` 类仍在 add/remove 但无对应样式;建议清理 |
| P4 | 心跳无抖动 | 60s 固定间隔无随机抖动,多客户端同时心跳存在瞬时请求峰;当前规模可忽略,接入量级后可加 ±10s 抖动 |
