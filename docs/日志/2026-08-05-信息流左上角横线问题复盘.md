# 2026-08-05 信息流左上角横线闪烁问题复盘

> 日期:2026-08-05。
> 类型:排查复盘与经验总结。
> 性质:历史快照。
> 范围:WebUI 信息流首屏「左上角一条横线闪烁」问题的根因定位、修复与排查过程教训。
> 说明:记录事实与结论;当前行为以源码为准。

## 现象

每次打开网页,帖子容器(信息流)左上角会有一条细横线快速闪一下。

## 根因

`webui/static/css/components.css` 中的 `.feed.is-refreshing::before` 伪元素:

```css
.feed.is-refreshing::before {
  content: '';
  position: absolute;
  top: -2px;   /* 贴在信息流容器顶部 */
  left: 0;     /* 靠左 */
  width: 35%;
  height: 2px; /* 一条 2px 横线 */
  background: var(--accent-primary);
  animation: feedProgress 0.9s ease-in-out infinite; /* 横向扫过 */
}
```

它是一条 2px 高、强调色的顶部进度条。`main.js` 的 `loadPosts()` 在非首屏(`!append` 且 feed 已有内容)分支会给容器加 `is-refreshing` 类,该伪元素随之出现并横向扫过一遍——视觉上正是「左上角横线闪烁」。`resetFeed()` 不清空容器,因此页面加载时 feed 若已有内容就会触发。

## 修复

- 删除 `.feed.is-refreshing::before` 规则及 `@keyframes feedProgress`;JS 中 `is-refreshing` 类的添加/移除逻辑保持不变,只是不再有视觉表现。
- `index.html` 中 `components.css` 链接更新缓存版本 `?v=20260805-feed-bar-off`,确保浏览器加载新样式。
- 验证:按用户实测,横线不再出现。

## 排查过程回顾

| 次序 | 假设 | 改动 | 结果 |
|---|---|---|---|
| 1 | 圆角与 3px 透明左边框的绘制接缝导致边框闪烁 | `.post-card` 的 `border-left: 3px solid transparent` 改为 hover 时 `inset 2px 0 0` 阴影 | 未修复,且改变了视觉 |
| 2 | 骨架屏复用 `.post-card` 类,过渡/悬停规则作用于占位卡 | 骨架屏加 `.skeleton-card` 类,禁用过渡与悬停 | 未修复 |
| 3 | 信息流顶部进度条伪元素 | 直接删除 `.feed.is-refreshing::before` 及其关键帧 | 修复 |

## 经验教训

1. **症状吻合的可疑选择器要优先查看,而不是先脑内推理排除。** 第一次全量 grep 时 `.feed.is-refreshing::before` 就已出现在结果中,与「左上角、横线、闪烁」的症状几乎一一对应;但当时用「冷启动走骨架屏分支、不会触发 `is-refreshing`」的假设把它排除,导致多浪费两轮猜测。该假设本身也不成立:`resetFeed()` 不清空容器,feed 已有内容时重新加载即会进入添加 `is-refreshing` 的分支。
2. **伪元素(`::before`/`::after`)是「莫名出现的线/色块」类问题的高概率来源**,排查时应第一时间定位。
3. **疑似元素直接禁用验证,比推导触发时序更快更可靠。** 正确做法是:先改一个开关(删除或 `display: none`),让用户实测,再回头补全触发机制的解释。
4. **猜测性改动会留下非根因的历史修改,且可能改变既有视觉**,应尽快回退,只保留真修复。

## 当前代码状态

- 保留(真修复):删除 `.feed.is-refreshing::before` 与 `@keyframes feedProgress`;缓存版本号更新。
- 建议回退(非根因):第 1 次改动 `.post-card` 左边框改内嵌阴影(改变了视觉);第 2 次改动 `.skeleton-card` 类(无害代码卫生,可留可退)。
