# 2026-08-06 WebUI 导航去重与前端模块拆分

> 日期:2026-08-06。
> 类型:实现记录。
> 性质:历史快照。
> 范围:删除与「热门」功能重叠的「大家在聊」导航入口,并将 webui 前端帖子弹窗逻辑从 main.js 拆分为独立模块 post-modals.js。
> 说明:记录本轮实现事实、关键技术细节与静态验证边界;当前行为以源码为准。

## 背景

1. 用户反馈:侧栏「大家在聊」与顶部「热门」功能重叠,要求删除;并询问是否有必要拆分成独立页面。
2. 排查结论:点击「大家在聊」后调用 `selectFeed('discussed', 'popular')`,与顶部「热门」按钮 `selectFeed('market', 'popular')` 指向同一查询(按点赞数、回复数、创建时间倒序),数据与 UI 完全重复,无独立逻辑。删除其一即可,「热门」作为唯一入口保留。
3. 拆页评估:最新/热门/关注/收藏/我的小摊本质是同一帖子列表的不同查询条件,单页切换已复用加载、分页与卡片交互;用户最终确认不拆独立页面,改为拆分前端代码文件。

## 实现内容

### 导航去重

1. `webui/static/index.html`:删除侧栏「逛一逛」下 `data-view="discussed"` 的「大家在聊」链接;顶部「热门」按钮(`data-feed="popular"`)保留。
2. `webui/static/js/main.js` `bindNavigation()`:视图链接统一 `selectFeed(view, 'latest')`,移除 `view === 'discussed' ? 'popular' : 'latest'` 的特殊分支。
3. 全局搜索确认:工作区不再存在 `discussed` /「大家在聊」引用。

### 前端模块拆分

4. 新建 `webui/static/js/post-modals.js`,导出工厂 `createPostModalController({ getCurrentUser, resetFeed, requireUser })`,集中帖子相关弹窗逻辑:
   - `showCreatePostModal` / `showReplyModal`(发帖、回复);
   - `showPostDetail(postId, attachPostCardListeners)`(详情 + 回复列表 + 关注作者);
   - `showEditPostModal` / `handleDeletePost`(编辑、删除);
   - 内部辅助 `parseTags` / `escapeText`。
5. `webui/static/js/main.js` 瘦身:删除上述函数与 `parseTags`/`escapeText` 辅助函数,移除不再使用的 API 导入(`createPost`/`deletePost`/`fetchPost`/`toggleFollow`/`updatePost`);新增 `import { createPostModalController } from './post-modals.js?v=20260806-post-modules'`。
6. 接线:
   - `init()` 在 `await restoreSession()` 之后创建 `postModals = createPostModalController({ getCurrentUser: () => currentUser, resetFeed, requireUser })`;
   - 卡片事件(详情/回复/编辑/删除)与 FAB(发布)改为调用 `postModals.*`;
   - 详情弹窗内的回复卡片绑定通过 `attachPostCardListeners` 回调传入模块。

## 关键技术细节与坑

1. **依赖注入而非模块间直接引用**:post-modals.js 需要读当前用户、刷新 feed、拦截未登录;若直接 import main.js 会形成循环依赖(main.js 也 import post-modals.js)。改为工厂注入回调 `getCurrentUser`/`resetFeed`/`requireUser`,模块无循环依赖。
2. **`getCurrentUser` 用箭头函数保持闭包实时性**:`() => currentUser` 每次调用读取最新 `currentUser`,登出/登录切换后弹窗模块无需重建即可感知用户变化;若传值快照,登录态变化后行为会错。
3. **初始化时序**:`postModals` 在 `init()` 中于 `restoreSession()` 后、`loadPosts()`/FAB 绑定前创建;卡片监听只在 `loadPosts`/`resetFeed` 渲染后附加,均晚于控制器创建,不存在访问未初始化 `postModals` 的路径。`postModals` 声明为模块级 `let`,供卡片事件闭包读取。
4. **行为保持**:迁移时逐项比对原实现——提交成功后的 `resetFeed()`(内部已重置 `currentPage = 1`)、未登录拦截走 `requireUser()`(等价原 `if (!currentUser) { showAuthModal('login'); return; }`)、详情弹窗 `attachPostCardListeners(modal)` 绑定回复卡片、编辑/删除/回复的提示文案与错误分支全部保留。
5. **详情弹窗回调**:`showPostDetail` 接收 `attachPostCardListeners` 作为参数,由 main.js 传入,模块不直接持有 DOM 容器,职责边界清晰。
6. **缓存版本号**:新模块导入带 `?v=20260806-post-modules`;但 `index.html` 中 main.js 的 script 标签版本号仍是 `?v=20260806-stable-first-paint`,未随内容更新递增,依赖后端 `Cache-Control: no-cache, must-revalidate` 兜底,按项目惯例应补递增(见审查报告 P3)。
