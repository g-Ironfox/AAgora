# 2026-08-06 在线用户心跳与首屏闪烁修复

> 日期:2026-08-06。
> 类型:实现记录。
> 性质:历史快照。
> 范围:在线用户统计改为 Redis 活跃窗口、HTTP 心跳链路、Redis 配置环境变量化、首屏两阶段渲染闪烁修复。
> 说明:记录本轮实现事实、关键技术细节与静态验证边界;当前行为以源码为准。

## 背景

1. 侧栏「在线用户」原实现返回 `database["users"].count_documents({})`(注册用户总数),且只在页面初始化时请求一次,不是实时在线人数,属数据语义 bug。
2. 刷新页面时帖子区闪烁、从下往上跳:根因是首屏两阶段渲染——先插入 3 张带 `pulse` 动画的骨架卡片,请求返回后再整体替换成 20 张真实帖子;登录区初始为空,`/auth/me` 返回后再插入按钮/头像,顶部同步重排。

## 实现内容

### 在线用户:Redis ZSET 活跃窗口

1. 新增 `POST /api/v1/presence`(需登录):`ZADD presence:users <member=user_id> <score=当前 unix 时间戳>`,幂等,同一用户多标签页/多设备只占一个 member。
2. `GET /api/v1/stats` 的 `users` 改为:先 `ZREMRANGEBYSCORE presence:users -inf <now-120s>` 清理过期,再 `ZCOUNT presence:users <now-120s> +inf` 统计窗口内活跃用户数。
3. 窗口 `PRESENCE_TTL_SECONDS = 120`,前端心跳间隔 `PRESENCE_INTERVAL_MS = 60_000`,容忍一次心跳丢失仍在线。
4. 退出登录:先按 Cookie token 哈希查 session 取 `user_id`,删 session 后 `ZREM presence:users <user_id>`,立即从在线名单移除。

### 前端心跳链路

5. `api.js` 新增 `sendPresenceHeartbeat()`(`POST /presence`)。
6. `main.js` 新增 `heartbeat()`:未登录或页面隐藏(`visibilityState === 'hidden'`)时跳过;401 静默(会话过期不报错刷屏),其他错误 console.error。
7. 生命周期:
   - `init()` 在 `restoreSession()` 成功后 `startPresenceHeartbeat()`(立即心跳一次 + 60s 定时)。
   - 登录/注册成功后 `startPresenceHeartbeat()`(先 `clearInterval` 再重建,防重复定时器)。
   - 登出成功后 `stopPresenceHeartbeat()`。
   - `visibilitychange` 回到可见时补发一次心跳并刷新统计。

### 首屏闪烁修复

8. 移除 `loadPosts()` 首屏的 `renderSkeleton()` 分支:空 feed 时不再先画假卡片,直接加 `is-refreshing`/`aria-busy` 等真实响应一次性渲染。`renderSkeleton()` 与骨架 CSS 成为死代码(保留,待清理)。
9. 移除 `.skeleton` 的 `animation: pulse` 与 `@keyframes pulse`(静态灰块,防残留闪烁)。
10. 登录区布局稳定化:`.auth-actions` 加 `min-width: 190px` + `justify-content: flex-end`(移动端 108px),异步渲染按钮/头像不再横向挤动导航。
11. 静态资源缓存版本号更新:`main.js?v=20260806-stable-first-paint`、`layout.css?v=20260806-stable-auth`、`components.css?v=20260806-skeleton-static`、`api.js?v=20260806-presence`(配合后端 `Cache-Control: no-cache, must-revalidate`)。

### Redis 配置环境变量化

12. `auth.py` 新增共享 `redis_client`:`REDIS_HOST`(默认 `redis`)、`REDIS_PORT`(默认 `6379`),`decode_responses=True`。
13. `docker-compose.yml`:
    - webui 增加 `depends_on: redis: condition: service_healthy`。
    - webui 环境注入 `REDIS_HOST: ${REDIS_HOST:-redis}`、`REDIS_PORT: ${REDIS_PORT:-6379}`。
    - 顺带把 `MONGO_HOST/PORT` 也改为 `${...:-默认}` 形式,统一由 `.env` 驱动。
14. `.env` / `.env.example` 增加 `REDIS_HOST=redis`、`REDIS_PORT=6379`,注释同步为「消费 MONGO_*、REDIS_* 与可选的 MONGO_URI」。

## 关键技术细节与坑

1. **ZSET 而非 Hash/Key-Expire**:member 天然去重(按 user_id,不计设备数),score 即时间戳可直接做窗口计数与清理;比每个用户一个 TTL key 少维护多把钥匙。
2. **统计接口带写副作用**:`get_stats` 每次调用都执行 `ZREMRANGEBYSCORE` 清理过期成员,避免 Redis 端另配过期任务;GET 带写操作属取舍,并发下 ZSET 操作原子,可接受。
3. **登出需二次查询**:Cookie 里只有 token 哈希,拿不到 user_id,必须先 `sessions.find_one` 查回 session;若 session 已被 TTL 清理,`zrem` 跳过。
4. **窗口与间隔比例 2:1**:60s 心跳、120s 窗口,网络抖动丢一次心跳不掉线;代价是离线判定最多滞后 2 分钟。
5. **401 静默策略**:心跳遇 401(会话过期)只跳过不报错,避免每隔 60s 刷一次错误;页面不主动跳登录,由用户下一次操作触发。
6. **多标签页语义**:同一用户多个标签页只计 1 人(ZSET 按 user_id 去重),符合「在线用户」而非「在线连接数」的语义;任一标签页登出会移除该用户,其余标签页 60s 内心跳会把它加回,存在短暂波动(已知,可接受)。
7. **Redis 故障无降级**:`get_stats`/`heartbeat` 直接调 redis_client,Redis 不可用时抛异常(前者 500、后者前端 console.error);未做 try/except 降级(如返回 `users: null`),本轮未处理。
8. **死代码**:`renderSkeleton()` 及骨架 CSS 类已无调用方;`.is-refreshing` 类仍在 add/remove,但对应 `::before` 进度条规则上轮已删,当前无视觉效果。
9. **`.env` 不入库**:`.env` 含真实口令被 `.gitignore` 排除,模板 `.env.example` 同步;部署时需自行复制填充。
