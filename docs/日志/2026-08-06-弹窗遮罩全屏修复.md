# 2026-08-06 弹窗遮罩全屏修复

> 日期:2026-08-06。
> 类型:实现记录。
> 性质:历史快照。
> 范围:帖子详情弹窗遮罩未占满屏幕宽度问题的跟进修复。
> 说明:记录本轮实现事实、关键技术细节与静态验证边界;当前行为以源码为准。

## 背景

1. 用户反馈:上一轮遮罩修复(见 [`2026-08-06-弹窗遮罩修复.md`](2026-08-06-弹窗遮罩修复.md))之后,帖子详情弹窗的遮罩仍然没有占满整个屏幕宽度。
2. 排查过程:
   - 先核对挂载位置:所有弹窗(含帖子详情)均由 `webui/static/js/components.js` 的 `showModal()` 创建并 `document.body.appendChild(modal)` 挂到 `<body>` 直接子节点,位于 `.app-layout`(CSS Grid)之外,因此「父 div 是 grid、宽度被限制」的怀疑不成立;
   - 问题集中在 `.modal-overlay` 自身的尺寸声明:初始态为 `position: fixed; top/right/bottom/left: 0; width: auto; height: 100vh/100dvh`。`width: auto` 的 fixed 元素宽度由内容与 `left/right` 拉伸共同决定,在滚动条/内容宽度等场景下不保证铺满视口宽,是「没占满宽度」观感的直接嫌疑。

## 实现内容

1. `webui/static/css/components.css` 的 `.modal-overlay`:
   - 第一步(临时方案):将 `width: auto` 改为 `width: 100vw`;
   - 第二步(用户反馈仍异常后):彻底精简为 `position: fixed; inset: 0;`,删除全部显式 `width` / `height` / `min-height` 声明。`inset: 0` 同时设定上右下左四个偏移,由 fixed 包含块(视口)拉伸决定宽度与高度,是标准的全屏遮罩写法,不依赖任何视口单位。
2. `webui/static/index.html`:`components.css` 缓存版本号由 `?v=20260806-modal-overlay` 递增为 `?v=20260806-modal-overlay-fullscreen`,确保客户端拉取新样式。

## 关键技术细节与坑

1. **「父 div 的问题」怀疑不成立**:`.app-layout` 是 `display: grid`,但弹窗挂在 `document.body` 直接子节点,不在 grid 容器内,不受其列宽约束。排查时先核对 `showModal()` 的挂载点,可避免误改父容器或 grid 布局。
2. **`width: 100vw` 的坑**:`100vw` 在 Windows 含纵向滚动条时等于「视口宽 + 滚动条宽」,会略超可视宽度;弹窗打开时 `body` 已被 `overflow: hidden` 锁滚动,超出部分被裁掉,通常无感,但语义不严谨。`inset: 0` 的拉伸方式与滚动条无关,更稳健,故最终没有保留 `100vw`。
3. **fixed 元素 `width: auto` 的行为**:`position: fixed` 且 `left/right` 同时非 auto 时,宽度由包含块拉伸决定;但显式声明 `width: auto` 与 `height` 会改变计算路径,易出现「该铺满却按内容/百分比收缩」的观感问题。全屏遮罩应只用 `inset: 0`(或 `width/height: 100%`),二者选一,不要混写。
4. **`100vh` vs `100dvh` 不再需要**:`dvh` 用于处理移动端动态地址栏;本轮删除显式高度后,`inset: 0` 天然覆盖动态视口,顺带消除了旧写法里 `vh`/`dvh` 双行回退的维护负担。
5. **`min-height` 冗余**:旧写法 `width: 100vw; min-height: 100vh/100dvh` 与 `inset: 0` 并存属于冗余声明,容易造成「到底是哪个在起作用」的困惑;本轮一并清除,避免后续误读。
6. **缓存版本号必须同步**:样式改动后若版本号不变,浏览器在强缓存窗口内可能仍用旧样式,把「未修复」误报为「未生效」。本轮已按项目惯例递增为 `-fullscreen`;后端 `Cache-Control: no-cache, must-revalidate` 提供兜底。

## 静态验证

1. VS Code 静态诊断:`components.css`、`index.html` 均无错误。
